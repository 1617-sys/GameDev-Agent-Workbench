## 目标

采集最小试玩事件，形成与 PrototypeVersion 绑定的可靠指标，并让 AI 基于聚合数据生成可追溯的平衡建议。

## 范围

- 落地 PlaytestSession、事件批次和聚合结果的数据模型/API。
- Runtime 上报开始、收集、受击、胜负、重开和结束事件。
- 客户端批量发送，服务端执行认证、归属、限流、大小限制和幂等去重。
- 聚合通关率、耗时、得分、受击、失败和重试指标。
- 前端展示单版本摘要和两版本指标对比。
- Python Agent 基于配置和聚合指标生成平衡建议 Artifact。
- 增加重复批次、乱序、越权、超限和并发会话测试。

## 非目标

- 不采集键盘明细、鼠标轨迹、Prompt 原文和个人敏感信息。
- 不做实时大数据平台、Kafka、复杂漏斗或热力图。
- 不让 AI 自动修改或发布原型版本。
- 不做公开排行榜和社交统计。

## 约束

- 每个事件必须绑定认证用户、项目、版本、会话和序列号。
- 相同批次重放不能重复计数。
- 事件数量、字段长度、时间范围和请求频率必须受限。
- 聚合结果来自服务端持久化数据，不信任客户端汇总。
- AI 只能读取必要的聚合指标和配置，不读取敏感会话数据。

## 验收标准

- [ ] 一次完整试玩形成唯一会话和正确终局摘要。
- [ ] 重复、乱序和超限事件被安全处理且不会重复统计。
- [ ] 指标按 PrototypeVersion 正确隔离。
- [ ] 用户可以比较两个版本的通关率、耗时和失败指标。
- [ ] 平衡建议标明数据范围、版本和生成来源。
- [ ] Telemetry 不包含 Token、Prompt 原文或敏感信息。

## 审查清单

- 批次重试是否导致统计翻倍。
- 客户端能否伪造其他项目或版本的数据。
- 会话结束后是否继续接收无界事件。
- AI 建议是否把少量样本描述成确定结论。

## 完成定义

- Telemetry 幂等、安全和聚合测试通过。
- 指标能够实际帮助比较和调节轻量原型。
- AI 建议可追溯且不会自动覆盖历史版本。
