# V3-FE-02：导出页面入口与状态机

> 状态：`DONE`
>
> 前置任务：`V3-FE-01`
>
> 执行方式：`VIBE`（状态机先行，逐状态生成 UI）
>
> 预计工时：60-90 分钟

## 目标

在“原型版本与调参”页面提供可理解、可恢复的导出入口，让用户看到作业状态、完成后下载，并能对失败作业执行同一冻结输入重试。

## 状态模型

```text
IDLE
  -> CREATING
  -> PENDING -> POLLING -> COMPLETED -> DOWNLOADING -> IDLE
                         -> FAILED -> RETRYING -> PENDING|COMPLETED|FAILED
```

后端状态只接受 `PENDING`、`COMPLETED`、`FAILED`；`CREATING`、`POLLING`、`DOWNLOADING`、`RETRYING` 是前端展示状态。

## 范围

- 在选中版本的摘要区域增加“导出离线原型包”入口。
- 未生成当前版本平衡建议时禁用，并说明前置条件。
- 展示状态、尝试次数、文件大小、摘要或稳定错误码。
- `COMPLETED` 后下载 ZIP；重复点击不得并发创建多个作业。
- `PENDING` 使用 GET 观察持久化状态，采用有上限的短轮询和退避。
- `FAILED` 展示“重试同一冻结输入”，调用 retry 而不是生成新幂等键创建新作业。
- 切换 PrototypeVersion 时清理旧版本的临时 UI 状态。
- 页面卸载或版本切换时取消轮询，不让旧响应覆盖新版本。
- 对下载失败与导出作业失败使用不同文案。

## 非目标

- 不增加导出历史列表、删除作业或后台通知中心。
- 不允许用户编辑 ZIP 内容、导出格式或冻结输入。
- 不重新生成平衡建议，不修改 PrototypeVersion。
- 不使用固定长 sleep 掩盖竞态。

## Vibe 执行约束

1. 先让模型输出状态转移表和事件清单，人工确认后再生成 Vue 代码。
2. 一次只实现一条主路径：成功导出、PENDING 查询、失败重试、版本切换清理。
3. 每完成一条路径立即补测试，禁止最后一次性补齐所有测试。
4. 模型不得自行发明后端状态、字段或新 API；未知状态进入受控错误展示。
5. 最终人工 diff 检查重复提交、陈旧异步响应和按钮可访问性。

## 验收标准

- [x] 当前版本有建议时可以创建导出作业。
- [x] 按钮在请求期间禁用，不产生重复作业。
- [x] PENDING 通过可观察状态查询进入终态。
- [x] COMPLETED 下载后正确恢复交互状态。
- [x] FAILED 显示错误码并能重试原 job。
- [x] 切换版本不会展示或下载上一版本作业。
- [x] 按钮和状态在桌面与 375px 视口可用。
