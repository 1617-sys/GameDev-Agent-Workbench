# V3-02：Phaser H5 Runtime 正式化

> 状态：`DONE`
>
> 前置任务：`V3-01`
>
> 推荐模型：`gpt-5.5` 状态机审查，`gpt-5.4` 组件与样式实现
>
> 预计工时：14-20 小时

## 目标

将现有几何图形验证场景升级为一个完整但轻量的 `arcade_collect` H5 小游戏 Runtime，使其可以在桌面和手机浏览器完成开始、游玩、结算和重开。

## 范围

- 实现明确的 READY、PLAYING、PAUSED、WON、LOST 状态。
- 增加触摸/虚拟方向控制，并保留键盘操作。
- 增加倒计时、得分、生命/受击保护、出口解锁和结算。
- 支持水平/垂直巡逻、障碍和世界边界碰撞。
- 使用仓库内置白名单 Sprite/音效 manifest，提供资源加载失败降级。
- 保持固定随机种子下的初始状态可复现。
- 补充 Runtime 状态、配置边界、资源降级和移动视口测试。

## 非目标

- 不增加第二模板、地图编辑器、高级寻路、技能树或多人玩法。
- 不引入 Unity、Godot 或重量级物理插件。
- 不生成或训练美术资源。
- 不实现版本管理和 Telemetry 后端。

## 约束

- Runtime 只消费已验证的 GameConfig 2.0。
- UI 状态和 Phaser Scene 状态必须一致，销毁组件时释放 Game 实例和监听器。
- 触摸控件尺寸稳定，不能遮挡 HUD 和游戏关键区域。
- 单个 Sprite 或音效失败时使用本地占位资源，不让游戏白屏。
- 不执行配置中的任意函数、HTML 或资源 URL。

## 验收标准

- [x] 一个原型可以完整开始、暂停、继续、胜利/失败、结算和重开。
- [x] 键盘和手机触摸操作均可完成游戏。
- [x] 倒计时、生命、得分、目标和出口状态符合配置。
- [x] 相同配置和种子生成相同初始场景。
- [x] 非关键资源失败时 Demo 仍可运行并给出可读提示。
- [x] 桌面与 375px 移动视口不存在关键遮挡或横向溢出。

## 验证命令

```powershell
cd frontend-vue
npm run test:game-config
npm run test:runtime-smoke
npm run test:unit
npm run build
```

## 审查清单

- Scene 重开后是否重复注册输入、碰撞和计时器。
- 状态是否可能在结束后继续计分或上报事件。
- 移动端触摸是否触发页面滚动或遮挡画布。
- 配置或资源异常是否造成白屏。

## 完成定义

- 自动测试和人工桌面/手机试玩通过。
- Runtime 形成一段完整 3-10 分钟小游戏体验。
- diff 不引入第二玩法和任务外框架。
