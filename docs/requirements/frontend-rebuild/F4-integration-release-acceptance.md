# F4：前端集成与发布验收

> 状态：`TODO`
>
> 前置任务：`F1`、`F2`、`F3`
>
> 推荐模型：`gpt-5.5` 审查，`gpt-5.4` 执行机械修复
>
> 任务类型：集成验证 / Code Review / 发布收口

## 背景

F1-F3 完成后，需要从真实 Docker 环境验证完整用户旅程，并检查安全、响应式、回归和文档一致性。本任务以发现和修复阻断发布的问题为主，不继续扩展产品功能。

## 目标

```text
Docker 启动
-> 注册/登录
-> 创建/选择项目
-> 提交生成
-> 查看进度
-> 查看产物与游戏预览
-> 形成可重复验收记录
```

## 必读上下文

- `docs/frontend-rebuild-design.md`
- F1-F3 三张任务卡及其实际 diff
- `frontend-vue/package.json`
- `frontend-vue/tests/`
- 前后端 Dockerfile、`docker-compose.yml` 和启动文档
- `docs/AI_COLLABORATION.md` 的 Harness、审查、纠错和完成定义章节
- `docs/PITFALLS.md`

## 范围

- 审查 F1-F3 的整体 diff、接口契约、认证安全和页面状态。
- 更新或新增一条覆盖主用户旅程的浏览器 E2E。
- 在 Docker 环境完成真实构建和主链路验收。
- 检查桌面和 375px 移动视口中的可用性。
- 修复验收中发现的阻断级和高风险问题。
- 更新必要的启动/演示说明，并沉淀真实踩坑。
- 输出简短验收结果，不制造大量截图和重复 evidence。

## 非目标

- 不增加新页面、新业务模块、新游戏类型或复杂视觉效果。
- 不进行与验收无关的全仓重构和依赖升级。
- 不为追求覆盖率补大量低价值测试。
- 不修改后端契约，除非存在有证据的发布阻断；发生时应单独建卡。
- 不重新执行与本次前端无关的全部 R7 性能和故障演练。

## 约束

- E2E 必须验证真实可见行为，不能只断言内部变量或 Mock 成功。
- 测试账号和数据必须可清理，不把真实密码写入仓库。
- 修正必须是最小改动，并带有对应回归验证。
- 不因 E2E 不稳定而增加任意 sleep；等待可观察的网络或页面状态。
- Code Review 先列问题和风险，再实施修复。
- 不覆盖任务开始前的用户 WIP，不提交生成报告和临时截图。

## 验收标准

- [ ] 前端单元测试、GameConfig 测试和 build 全部通过。
- [ ] Docker 服务可以构建并健康启动。
- [ ] 浏览器 E2E 覆盖注册/登录、项目创建、工作流提交和运行详情主链路。
- [ ] 至少人工验证一次成功结果与游戏预览。
- [ ] 401、请求失败、空项目、运行失败和空 Artifact 有可理解状态。
- [ ] 不存在 UUID、工作流 Key 和幂等键的用户输入项。
- [ ] 没有 Token 持久化泄漏、未清理 SSE 或不可信 HTML 执行问题。
- [ ] 375px 移动端和桌面主流程无重叠、溢出和不可点击控件。
- [ ] 启动说明与实际端口、命令和账号获取方式一致。

## 验证命令

```powershell
cd frontend-vue
npm run test:unit
npm run test:game-config
npm run build

cd ..
docker compose up -d --build
docker compose ps

cd frontend-vue
npm run test:e2e:main

cd ..
git diff --check
git status --short
```

如仓库的 Compose 文件或主 E2E 命令在实施前已经变化，应以当前实际脚本为准更新本卡，不得伪造通过结果。

## 人工验收

1. 使用全新业务账号注册并登录。
2. 创建一个项目，刷新后确认项目仍存在。
3. 输入游戏想法并连续点击提交按钮，确认只产生一次有效提交。
4. 查看运行步骤，刷新详情页确认可以恢复。
5. 验证失败提示、取消或重试中的至少一个异常路径。
6. 查看产物并打开 Phaser 游戏预览。
7. 在桌面和 375px 宽度各走一次主流程。

## 审查清单

- 是否存在只在本地 Vite 可用、Docker 代理或路径下失败的问题。
- 是否把数据库账号写成业务登录示例。
- 是否有按钮重复提交、SSE 泄漏、状态倒退或刷新丢失。
- 是否有未处理 Promise、控制台敏感日志和原始 HTML 注入。
- 是否为了通过测试修改断言而没有修正真实行为。
- 是否夹带报告、截图、构建产物或任务外文件。

## 完成定义

- 所有验收标准通过，失败项有真实记录且不存在发布阻断。
- 自动化验证命令结果可重复，Docker 主链路可运行。
- 人工验收完成，关键异常路径已检查。
- 真实踩坑已经按 `docs/PITFALLS.md` 的格式沉淀。
- 最终 diff 通过范围和安全审查，可以形成独立前端重建提交或 PR。
