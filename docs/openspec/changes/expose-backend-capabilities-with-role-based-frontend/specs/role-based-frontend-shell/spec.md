## Purpose

为不同权限用户提供清晰、可发现且安全的前端工作区，使业务能力、项目高级能力和管理员诊断能力按后端授权结果呈现，而不是依赖隐藏按钮实现访问控制。

## ADDED Requirements

### Requirement: 后端权威的角色与能力
系统 SHALL 以认证响应或专用能力端点返回的权限作为前端展示与后端授权的共同事实来源，前端 MUST NOT 通过本地标志自行提升权限。

#### Scenario: 普通用户登录
- **WHEN** 普通用户完成认证
- **THEN** 导航仅显示其有权访问的项目和业务功能

#### Scenario: 伪造管理员路由
- **WHEN** 普通用户直接访问管理员 URL 或构造管理员 API 请求
- **THEN** 页面显示无权限状态且后端拒绝请求

### Requirement: 分层导航
系统 SHALL 提供普通用户工作区、项目高级工作区和管理员/诊断工作区，并在页面标题、导航和危险操作样式上清楚区分层级。

#### Scenario: 管理员发现诊断能力
- **WHEN** 具有管理员能力的用户进入应用
- **THEN** 可以从主导航到达 Dashboard、Prompt 运维、指标和诊断页面

#### Scenario: 普通用户使用核心流程
- **WHEN** 普通用户进入项目
- **THEN** 可以发现生成、Artifact、知识库、版本、Player Run 和运行证据入口而不会看到内部实现术语

### Requirement: 安全状态呈现
所有角色页面 MUST 提供加载、空数据、权限不足、网络失败、部分数据缺失和重试状态，并 MUST NOT 展示密钥、Authorization、完整系统 Prompt、跨用户数据或内部堆栈。

#### Scenario: 后端返回权限不足
- **WHEN** 页面请求收到 403
- **THEN** 页面保留导航上下文并显示不可操作的权限说明，不回退成空数据或成功状态

#### Scenario: 敏感字段出现在响应
- **WHEN** 响应包含前端不应展示的敏感字段
- **THEN** 安全 DTO 和展示层均不渲染该字段
