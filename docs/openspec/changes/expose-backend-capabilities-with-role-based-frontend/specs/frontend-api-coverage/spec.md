## Purpose

建立后端 HTTP 能力与前端入口之间可机器校验的覆盖契约，确保每个端点都有明确分类、授权范围、用户入口或保留理由，并在持续集成阶段阻止新的静默遗漏。

## ADDED Requirements

### Requirement: 完整端点覆盖矩阵
系统 SHALL 为每个后端 HTTP 方法记录方法、规范化路径、所属领域、生命周期状态、允许角色、前端 API 适配器、页面入口和测试标识。

#### Scenario: 盘点现有端点
- **WHEN** 生成当前后端 API 契约
- **THEN** 覆盖矩阵包含所有 Controller 暴露的方法且不存在重复或未分类项

#### Scenario: 标记内部端点
- **WHEN** 某个端点仅供内部编排、兼容或非生产调试使用
- **THEN** 覆盖矩阵明确记录其状态、调用方和不提供普通用户入口的理由

### Requirement: 可访问端点具有前端映射
所有被分类为普通用户、项目高级用户或管理员/诊断的端点 MUST 具有类型一致的前端 API 适配器和至少一个可发现的页面操作或只读视图。

#### Scenario: 发现缺少前端映射
- **WHEN** 可访问端点没有前端适配器、页面入口或显式测试
- **THEN** 契约校验失败并指出端点与缺失项

### Requirement: 契约漂移门禁
持续集成 SHALL 对后端 OpenAPI、覆盖矩阵和前端 API 映射进行比较，并阻止未声明的新增、删除、方法变化、路径变化或请求响应契约变化。

#### Scenario: 后端新增接口
- **WHEN** 后端新增一个 Controller 方法但未更新覆盖矩阵和前端声明
- **THEN** CI 失败并要求分类该接口

#### Scenario: 有意保留内部接口
- **WHEN** 新接口被明确声明为内部且提供所有者、调用方和生命周期状态
- **THEN** CI 不要求普通用户页面，但仍要求权限和契约测试
