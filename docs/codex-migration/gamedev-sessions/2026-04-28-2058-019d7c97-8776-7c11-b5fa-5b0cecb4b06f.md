你现在这套项目的主流程可以理解成：

- 图片生成后上传 `MinIO`
- 前端通过 `/task/{uuid}` 轮询任务状态，拿到最终图片

**具体体现在哪里**

这说明你的类是 MVC 的 Controller，不是普通 Service。

2. 路由映射
- `@RequestMapping("/user")` 在 `[UserController.java](/F:/coe/java/AIGC-GameFlow/src/main/java/aigc/gameflow/controller/UserController.java#L17)`

这就是 Spring MVC 的“请求分发路径”。

- `@PostMapping("/login")`, `@PostMapping("/register")` 在 `[UserController.java](/F:/coe/java/AIGC-GameFlow/src/main/java/aigc/gameflow/controller/UserController.java#L22)`

这部分就是 MVC 负责把请求路由到对应处理方法。

4. 参数绑定
- `@RequestBody` 在 `[UserController.java](/F:/coe/java/AIGC-GameFlow/src/main/java/aigc/gameflow/controller/UserController.java#L23)`
- `@RequestBody` 和 `@PathVariable` 在 `[TaskController.java](/F:/coe/java/AIGC-GameFlow/src/main/java/aigc/gameflow/controller/TaskController.java#L26)`
- `@Valid` 在这些控制器方法里也有出现

这就是 Spring MVC 把 HTTP 请求体、路径参数自动绑定到 Java 对象的地方。

- 你现在大部分接口返回的是 `ApiResponse`

这属于 Spring MVC 的“返回值写回 HTTP 响应”。

6. 统一异常处理
- `[GlobalExceptionHandler.java](/F:/coe/java/AIGC-GameFlow/src/main/java/aigc/gameflow/controller/GlobalExceptionHandler.java#L11)`

这个是典型的 Spring MVC `@RestControllerAdvice + @ExceptionHandler` 用法，专门处理控制器层抛出的异常。

7. 异步/流式响应
- `[AgentController.java](/F:/coe/java/AIGC-GameFlow/src/main/java/aigc/gameflow/controller/AgentController.java#L26)` 里的 `SseEmitter`

- `spring-boot-starter-web`
- `Controller`
- `RequestMapping / GetMapping / PostMapping`
- `RequestBody / PathVariable / Valid`
- `RestControllerAdvice`
- `SseEmitter`

**面试时你可以这么说**

- `synchronized` 保证互斥

- 线程池是为了复用线程、减少创建开销

- 对象一般在堆上，方法调用在栈上

7. `JUC`

- `ReentrantLock` 支持可中断、可超时、可公平锁
- `CountDownLatch` 用来等待多个任务完成
- `CAS` 是无锁并发核心思想

8. `IO / NIO`

- `BufferedInputStream` 适合提升读取效率

### 175. Codex

你这段 `[JwtAuthenticationFilter.java](/F:/coe/java/AIGC-GameFlow/src/main/java/aigc/gameflow/config/security/JwtAuthenticationFilter.java)` 是为了把“**登录校验**”从业务代码里抽出来，放到请求进入 Controller 之前统一处理。

核心目的就 3 个：

1. `拦住没登录的人`
- 请求进来先看 `Authorization` 头里有没有 `Bearer token`
- 没有就直接放行到 Spring Security 处理，最后会被判成未登录
- 这样 `UserController`、`TaskController` 这些业务接口不用自己重复写校验

2. `把当前用户身份放进上下文`
- token 校验通过后，你这里会把 `userId` 放进 `SecurityContextHolder`
- 后面的 `TaskService.getCurrentUserId()` 才能拿到当前登录用户
- 这就是你项目里“谁在操作谁”的基础

3. `统一处理所有接口的鉴权`
- 不用每个接口单独判断 token
- 也不用在 Controller 里到处写登录检查
- 这样代码更干净，也更符合 Spring Security 的做法

你这段代码的实际链路是：

```text
请求进来 -> JwtAuthenticationFilter
-> 校验 token
-> 把 userId 放进 SecurityContext
-> Controller / Service 里直接拿当前用户
```

你项目里很多地方都依赖它，比如：
- `[TaskService.java](/F:/coe/java/AIGC-GameFlow/src/main/java/aigc/gameflow/service/TaskService.java)` 里 `getCurrentUserId()`
- `[TaskController.java](/F:/coe/java/AIGC-GameFlow/src/main/java/aigc/gameflow/controller/TaskController.java)` 里任务查询
- `[UserController.java](/F:/coe/java/AIGC-GameFlow/src/main/java/aigc/gameflow/controller/UserController.java)` 登录后发 token

所以简单说：

**这段代码是为了实现“无状态 JWT 鉴权”，让后端知道每个请求是谁发的，并且把鉴权逻辑统一前置。**

**二、Codex 提示词怎么写**

公司里程序员用 AI，不是直接说“帮我写个功能”，而是给它足够上下文、边界和验收标准。

一个好提示词通常包含 5 个部分：

```text
背景：这个项目是什么，当前模块负责什么
目标：我要你完成什么功能
范围：你可以改哪些文件，不要动哪些文件
约束：技术栈、代码风格、返回格式、异常处理要求
验收：完成后怎么验证，跑什么测试，看什么结果
```

**一个差的提示词**
```text
帮我加个任务列表功能
```

太空了。Codex 不知道你要接口、前端、数据库，还是文档。

**一个好的提示词**
```text
请帮我在当前 Spring Boot 项目里增加“我的任务列表”接口。

背景：
项目里已有 GenTask 实体、TaskService、TaskController，任务和用户通过 user_id 关联，当前用户从 SecurityContext 中获取。

目标：
新增 GET /task/mine 接口，返回当前登录用户的任务列表，按 create_time 倒序。

要求：
1. 不要改动 JWT 鉴权逻辑
2. 返回结构继续使用 ApiResponse
3. 查询时排除 is_deleted = 1 的任务
4. 如果当前用户未登录，返回统一异常
5. 保持现有代码风格

完成后：
请说明修改了哪些文件，并告诉我如何用 Postman 验证。
```

这就是公司里更接近真实开发的 AI 提示词。

**四、公司开发里最常见的提示词类型**

你要重点练这 6 类：

1. `读代码`

2. `加功能`
```text

```

3. `修 bug`
```text

```

4. `写接口文档`
```text

```

5. `代码审查`
```text
请 review 当前改动，重点检查空指针、权限、并发、异常处理和数据一致性。
```
