### 12. Codex

在 `GameAsset Copilot` 里，AI 的作用不是“炫技聊天”，而是模拟公司里运营/投放同学会做的素材分析工作，把图片素材变成可复用的业务信息。

核心用途有 4 个：

1. **自动看图打标签**

上传一张游戏素材图后，AI 分析图片内容，生成标签。

例如：

```text
角色立绘、二次元、赛博朋克、女性角色、近战武器、霓虹灯、适合年轻玩家
```

这些标签后面可以用于搜索、筛选、素材归类。

2. **生成画面描述**

AI 把图片内容总结成结构化描述。

例如：

```text
画面中是一名穿着未来科技风服装的女性角色，背景带有霓虹城市元素，整体风格偏赛博朋克和动作手游宣传图。
```

这能帮助面试官看到：你不是只存图片 URL，而是在做“素材理解”。

3. **提取投放卖点**

AI 根据图片提炼适合广告投放的卖点。

例如：

```text
高颜值角色
强战斗氛围
赛博都市题材
适合动作手游买量素材
视觉冲击力强
```

这贴近小游戏团队、广告投放、运营素材管理场景。

4. **生成广告文案**

AI 根据素材描述和卖点生成不同版本文案。

例如：

```text
广告标题：未来都市的最强猎手，等你集结！

短文案：霓虹闪烁，危机降临。选择你的角色，开启一场高燃战斗。

视频口播开头：如果你喜欢赛博朋克和动作战斗，这款游戏一定要试试。
```

还可以生成 `A/B 测试版本`，比如一个偏热血，一个偏剧情，一个偏福利。

所以这个项目里 AI 的价值是：

```text
图片素材
  -> AI 自动理解
  -> 标签/描述/卖点
  -> 广告文案
  -> 存入数据库
  -> 前端展示和复用
```

面试时可以这样说：

```text
我在项目里没有把 AI 当成单独聊天工具，而是把它嵌入到素材管理业务流程中。用户上传游戏素材后，系统会调用 Python FastAPI AI 服务，对图片进行标签识别、画面描述、卖点提取和投放文案生成，并将结果结构化保存到 MySQL，后续可以用于搜索、筛选和运营复用。
```

这比“我调用了大模型接口”更像实习开发项目。
